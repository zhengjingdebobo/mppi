# 上位机发送数据控制帧

更新时间：2026-07-29

本文记录当前工程中上位机发送给 STM32 的控制数据格式。内容以以下源码为准：

```text
keil/car_controlst.py
keil/test_v2_protocol.py
keil/CUBOT/Cubot_devices/nx16.h
keil/CUBOT/Cubot_devices/nx16.c
keil/CUBOT/Cubot_Calibration/chassis_rpm_calibration.h
keil/CUBOT/Cubot_Calibration/chassis_rpm_calibration.c
```

当前调试串口：

```text
端口：COM12
波特率：115200
数据位：8
停止位：1
校验位：无
```

## 1. 协议总览

当前存在三种上位机下行格式：

| 协议 | 帧长 | 用途 | 当前建议 |
| --- | ---: | --- | --- |
| 旧二进制协议 | 8 字节 | 旧前后、旋转、路径任务 | 仅兼容旧功能 |
| V2 二进制协议 | 16 字节 | 定速、定距、定角度、联合速度、停止和初始化 | 正常调试优先使用 |
| RPM 标定文本协议 | 不定长，以换行结尾 | 绕过运动学直接设置四轮 RPM | 仅标定固件使用 |

正常底盘固件和 RPM 标定固件不能同时控制车辆：

```c
CHASSIS_RPM_CALIBRATION_MODE = 0u  // 正常底盘控制
CHASSIS_RPM_CALIBRATION_MODE = 1u  // 专用RPM标定
```

## 2. V2 通用16字节帧

除 `0x28` 联合速度命令外，其余 V2 命令使用两个小端 `float32` 参数。

### 2.1 通用帧布局

| 字节 | 长度 | 字段 | 说明 |
| ---: | ---: | --- | --- |
| 0 | 1 | 帧头1 | 固定 `0xAB` |
| 1 | 1 | 帧头2 | 固定 `0xCD` |
| 2 | 1 | command_id | V2 命令ID |
| 3 | 1 | flags | 当前填写 `0x00` |
| 4～7 | 4 | param1 | IEEE754 `float32`，小端 |
| 8～11 | 4 | param2 | IEEE754 `float32`，小端 |
| 12 | 1 | sequence | 序号，每次发送递增，溢出后回到0 |
| 13 | 1 | reserved | 当前填写 `0x00` |
| 14 | 1 | checksum | `sum(byte[2]...byte[13]) & 0xFF` |
| 15 | 1 | 帧尾 | 固定 `0xDD` |

Python 等价构造：

```python
payload = struct.pack(
    "<BBffBB",
    command_id,
    flags,
    param1,
    param2,
    sequence,
    0,
)
checksum = sum(payload) & 0xFF
frame = b"\xAB\xCD" + payload + bytes([checksum, 0xDD])
```

STM32 使用 `(command_id, sequence)` 丢弃紧邻的重复帧。持续速度发布时，每一帧必须
使用新的 `sequence`。

### 2.2 V2命令表

| ID | 名称 | param1 | param2 | 是否持续重发 |
| ---: | --- | --- | --- | --- |
| `0x21` | `CMD2_MOVE_POLAR_SPEED` | 方向角，deg | 平移速度，m/s | 是 |
| `0x22` | `CMD2_MOVE_POLAR_DISTANCE` | 方向角，deg | 距离，m | 否 |
| `0x23` | `CMD2_ROTATE_IN_PLACE` | 旋转方向 | 旋转角度绝对值，deg | 否 |
| `0x24` | `CMD2_STOP` | 0 | 0 | 否 |
| `0x25` | `CMD2_INIT` | 0 | 0 | 否 |
| `0x26` | `CMD2_HEARTBEAT` | 0 | 0 | 可选 |
| `0x27` | `CMD2_ROTATE_SPEED` | `1.0`左转，`0.0`右转 | 角速度绝对值，deg/s | 是 |
| `0x28` | `CMD2_CHASSIS_VELOCITY` | 使用专用定点布局 | 使用专用定点布局 | 是 |

持续速度命令由 `CarController` 以 `10 Hz` 周期重发。STM32 当前连续速度链超时为
`500 ms`；上位机退出、串口断开或停止重发后，固件应在超时窗口内停车。

## 3. V2各控制命令

### 3.1 `0x21` 按方向角持续平移

参数：

```text
param1 = angle_deg
param2 = speed_mps
```

方向定义：

```text
0°   = 前
90°  = 左
180° = 后
270° = 右
```

负速度表示沿指定角度的反方向运动。

推荐Python接口：

```python
car.move_with_angle_speed(angle_deg, speed_mps)
```

示例：方向 `0°`、速度 `0.1 m/s`、序号 `1`：

```text
AB CD 21 00 00 00 00 00 CD CC CC 3D 01 00 C4 DD
```

### 3.2 `0x22` 按方向角定距离移动

参数：

```text
param1 = angle_deg
param2 = distance_m
```

推荐Python接口：

```python
car.move_with_angle_distance(angle_deg, distance_m, timeout)
```

该命令进入旧定距离闭环任务，不应周期重发。

### 3.3 `0x23` 定角度原地旋转

参数：

```text
param1 = direction
param2 = abs(angle_deg)
```

当前实车安装方向已经在Python接口中做过适配。线上实际推荐值为：

```text
param1 = 1.0：物理左转
param1 = 0.0：物理右转
```

不要根据固件内部枚举名称手工反推物理方向，优先调用：

```python
car.rotate_in_place_v2(turn_left, angle_deg, timeout)
```

### 3.4 `0x24` 停止

停止当前持续速度会话或闭环任务，并清除协议状态。

推荐Python接口：

```python
car.stop_v2()
```

示例，序号 `4`：

```text
AB CD 24 00 00 00 00 00 00 00 00 00 04 00 28 DD
```

### 3.5 `0x25` 初始化

复位任务、路径接收、速度会话及相关协议状态。

推荐Python接口：

```python
car.initialize_car_v2()
```

示例，序号 `5`：

```text
AB CD 25 00 00 00 00 00 00 00 00 00 05 00 2A DD
```

### 3.6 `0x26` 心跳

心跳只刷新链路存活时间，不产生新的运动目标。

```python
car.send_heartbeat_v2()
```

当前持续速度控制优先周期重发完整速度命令，而不是只发送心跳。

### 3.7 `0x27` 定角速度原地旋转

参数：

```text
param1 = 1.0：物理左转
param1 = 0.0：物理右转
param2 = 角速度绝对值，deg/s
```

推荐Python接口：

```python
car.rotate_with_speed(turn_left, angular_speed_dps)
```

示例：左转 `10 deg/s`、序号 `2`：

```text
AB CD 27 00 00 00 80 3F 00 00 20 41 02 00 49 DD
```

## 4. `0x28` vx/vy/wz联合定速度帧

`0x28` 保持16字节总帧长，但8字节参数区不再解释为两个 `float32`，而是三个
小端有符号 `int16` 定点数。

### 4.1 专用帧布局

| 字节 | 长度 | 字段 | 编码 |
| ---: | ---: | --- | --- |
| 0～1 | 2 | 帧头 | `AB CD` |
| 2 | 1 | command_id | 固定 `0x28` |
| 3 | 1 | flags | 当前为 `0x00` |
| 4～5 | 2 | vx | `round(vx_mps × 1000)`，小端 `int16` |
| 6～7 | 2 | vy | `round(vy_mps × 1000)`，小端 `int16` |
| 8～9 | 2 | wz | `round(wz_radps × 1000)`，小端 `int16` |
| 10～11 | 2 | payload_reserved | 当前填写 `0x0000` |
| 12 | 1 | sequence | 每次发送递增 |
| 13 | 1 | reserved | 当前填写 `0x00` |
| 14 | 1 | checksum | `sum(byte[2]...byte[13]) & 0xFF` |
| 15 | 1 | 帧尾 | `0xDD` |

单位和方向：

```text
vx：m/s，正数向前
vy：m/s，正数向左
wz：rad/s，正数逆时针/物理左转
```

分辨率：

```text
vx、vy：0.001 m/s
wz：0.001 rad/s
```

Python等价构造：

```python
vx_i16 = round(vx_mps * 1000)
vy_i16 = round(vy_mps * 1000)
wz_i16 = round(wz_radps * 1000)

payload = struct.pack(
    "<BBhhhHBB",
    0x28,
    0,
    vx_i16,
    vy_i16,
    wz_i16,
    0,
    sequence,
    0,
)
checksum = sum(payload) & 0xFF
frame = b"\xAB\xCD" + payload + bytes([checksum, 0xDD])
```

示例：

```text
vx = +0.100 m/s
vy = +0.050 m/s
wz = +0.200 rad/s
sequence = 3
```

定点原始值：

```text
vx = 100 = 0x0064
vy =  50 = 0x0032
wz = 200 = 0x00C8
```

完整帧：

```text
AB CD 28 00 64 00 32 00 C8 00 00 00 03 00 89 DD
```

推荐Python接口：

```python
car.set_chassis_velocity(vx_mps, vy_mps, wz_radps)
```

测试文件封装：

```python
send_velocity_xyz(car, vx_mps, vy_mps, wz_radps)
```

命令行示例：

```powershell
python keil\test_v2_protocol.py --port COM12 --only velocity --vx 0.10 --vy 0.05 --wz 0.20 --velocity-duration 5 --verbose
```

固件收到一帧后一次性调用：

```c
Chassis_SetVelocity(vx_mps, vy_mps, wz_radps);
```

当前限制：

```text
平移合速度 sqrt(vx² + vy²) 最大 0.50 m/s
角速度 |wz| 最大 0.60 rad/s
单轮补偿输出绝对值最大 13000 ERPM
```

输入超过限制时由固件速度链限幅，不应依赖上位机自行限幅。

## 5. 旧8字节二进制协议

### 5.1 帧布局

| 字节 | 长度 | 字段 | 说明 |
| ---: | ---: | --- | --- |
| 0 | 1 | 帧头 | 固定 `0xAA` |
| 1 | 1 | command_id | 旧命令ID |
| 2～5 | 4 | param | IEEE754 `float32`，小端 |
| 6 | 1 | checksum | `sum(byte[1]...byte[5]) & 0xFF` |
| 7 | 1 | 帧尾 | 固定 `0xDD` |

Python等价构造：

```python
payload = bytes([command_id]) + struct.pack("<f", param)
checksum = sum(payload) & 0xFF
frame = b"\xAA" + payload + bytes([checksum, 0xDD])
```

### 5.2 旧命令表

| ID | 名称 | param含义 |
| ---: | --- | --- |
| `0x01` | `CMD_MOVE_FORWARD` | 前进距离，m |
| `0x02` | `CMD_MOVE_BACKWARD` | 后退距离绝对值，m |
| `0x03` | `CMD_ROTATE_CCW` | 逆时针旋转角度，deg |
| `0x04` | `CMD_ROTATE_CW` | 顺时针旋转角度，deg |
| `0x05` | `CMD_STOP` | 0 |
| `0x06` | `CMD_INIT` | 0 |
| `0x07` | `CMD_PATH_TRACKING` | 路径点数量、坐标流或启动参数 |
| `0x08` | `CMD_SWITCH_PATH` | `0`立即切换，`>0.5`安全时切换 |

示例：前进 `0.2 m`：

```text
AA 01 CD CC 4C 3E 24 DD
```

示例：旧协议初始化：

```text
AA 06 00 00 00 00 06 DD
```

旧协议仍为历史任务服务。新增持续速度和联合速度控制应使用 V2，不要新增旧协议命令。

## 6. 旧路径点上传数据流

路径点上传沿用旧8字节帧，所有帧的命令ID均为 `0x07`。

普通上传并在收齐后启动：

```text
第1帧：param = 点数 n
第2帧：param = x1
第3帧：param = y1
第4帧：param = x2
第5帧：param = y2
...
```

仅上传、不立即启动：

```text
第1帧：param = -n
后续帧：x1、y1、x2、y2...
```

约束：

```text
点数范围：2～1000
坐标数据：float32小端
STOP会取消未完成的路径接收
```

上传完成后，`CMD_SWITCH_PATH (0x08)`：

```text
param = 0：立即切换
param > 0.5：等待安全条件后切换
```

## 7. RPM标定文本协议

仅当以下宏为 `1u` 时用于驱动车轮：

```c
#define CHASSIS_RPM_CALIBRATION_MODE 1u
```

每条命令使用ASCII文本，并以 `\n` 或 `\r\n` 结尾。

### 7.1 命令列表

```text
CALIBRATION_START
SET_RPM lf rf rb lb
STOP
CALIBRATION_STOP
```

示例：

```text
CALIBRATION_START\r\n
SET_RPM 800 800 800 800\r\n
STOP\r\n
CALIBRATION_STOP\r\n
```

注意轮序：

```text
LF RF RB LB
```

与函数参数保持一致：

```c
VESCMotorSetFourRPM(lf, rf, rb, lb);
```

当前标定保护：

```text
每轮目标绝对值最大：2000 ERPM
命令超时：500 ms
要求遥控器在线
遥控器产生运动输入时立即停止标定输出
```

正常模式 `CHASSIS_RPM_CALIBRATION_MODE=0u` 下，文本命令不会接管底盘。

## 8. 控制与安全注意事项

1. 同一时间只能有一个程序占用 COM12。
2. 正常运动前先发送 `CMD2_INIT`，结束时必须发送 `CMD2_STOP`。
3. 持续命令必须周期重发；不要只发送一帧后依赖车辆永久保持速度。
4. 遥控器保持最高优先级，遥控器运动输入会抢占串口控制。
5. `vx/vy` 是车体坐标速度，不是世界坐标速度。
6. `wz` 在 `0x28` 中使用 `rad/s`，而 `0x27` 的 `param2` 使用 `deg/s`，不要混用。
7. `0x28` 不能使用普通两个 `float32` 的 V2 打包函数，必须使用三路 `int16` 定点布局。
8. 校验和不包含帧头、校验和字段自身和帧尾。
9. 多字节数值全部使用小端序。
10. 修改命令ID、单位或定点比例时，必须同步修改Python和STM32两端。
