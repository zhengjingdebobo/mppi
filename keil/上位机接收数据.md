# USART1 上位机接收数据说明

更新时间：2026-07-27

用途：记录当前 STM32 底盘程序通过 USART1 向上位机发送的数据类型、帧格式、字段含义、发送频率和带宽占用。后续修改串口协议或上位机解析程序前，应先阅读本文。

## 1. 当前串口配置

上位机通信实际使用：

```text
UART：     USART1 / huart1
波特率：   115200
数据格式： 8N1
硬件流控： 无
TX：       PA9
RX：       PB7
发送方式： DMA
接收方式： DMA + UART IDLE
```

有效配置位于：

```c
#define AGENT_UART_HANDLE huart1
```

注意：`hardware_config.h` 中关于 USART6 的旧注释已经过时，实际代码使用的是 USART1。

相关文件：

```text
keil/CUBOT/Cubot_User_Config/hardware_config.h
keil/Src/usart.c
keil/CUBOT/Cubot_modules/chassis.c
keil/CUBOT/Cubot_devices/nx16.c
keil/CUBOT/Cubot_driver/drv_usart.c
```

## 2. 周期发送的数据总览

USART1 周期发送三类数据：

| 数据帧 | 长度 | 发送周期 | 设计频率 | 数据量 |
|---|---:|---:|---:|---:|
| 状态与里程计帧 | 86 B | 200 ms | 5 Hz | 430 B/s |
| VESC 反馈帧 | 78 B | 200 ms | 5 Hz | 390 B/s |
| IMU 遥测帧 | 166 B | 20 ms | 50 Hz | 8300 B/s |
| 合计 |  |  |  | 9120 B/s |

115200 baud、8N1 每个有效数据字节占用10个串行位，理论有效数据吞吐量约为：

```text
115200 / 10 = 11520 B/s
```

当前周期遥测占用率约为：

```text
9120 / 11520 = 79.2%
```

除周期发送外，底盘任务结束、失败或被停止时，`FinishTask()` 会立即额外发送一帧86字节的状态帧，以便上位机尽快获得最终结果。

## 3. 状态与里程计帧

发送函数：

```c
SendStatusAndOdometryToAgent()
```

### 3.1 基本格式

```text
帧头：   AA AA
总长度： 86字节
频率：   5 Hz，正常情况下每200 ms发送一次
校验：   byte[2] 至 byte[83] 的无符号8位累加和
帧尾：   DD
```

所有 `float` 均为 STM32 小端字节序，长度4字节。

### 3.2 字段定义

| 字节偏移 | 类型 | 字段 | 当前实际含义 |
|---:|---|---|---|
| 0～1 | uint8[2] | header | `AA AA` |
| 2 | uint8 | status | 当前命令状态 |
| 3 | uint8 | last_command_id | 最近执行或完成的命令 ID |
| 4～7 | float | current_x | 当前 X 位置 |
| 8～11 | float | current_y | 当前 Y 位置 |
| 12～15 | float | current_yaw | 当前控制航向角，现为 gyro 积分航向 |
| 16～19 | float | diag_0 | CAN1 FIFO0回调计数 |
| 20～23 | float | diag_1 | CAN1 FIFO1分发计数 |
| 24～27 | float | diag_2 | 最近收到的 CAN扩展 ID |
| 28～31 | float | cmd_vx | 调试用 X方向控制量 |
| 32～35 | float | cmd_vy | 调试用 Y方向控制量 |
| 36～39 | float | cmd_wz | 调试用旋转控制量 |
| 40～43 | float | lf_ref | 左前轮目标 ERPM |
| 44～47 | float | lf_fdb | 左前轮反馈 ERPM |
| 48～51 | float | rf_ref | 右前轮目标 ERPM |
| 52～55 | float | rf_fdb | 右前轮反馈 ERPM |
| 56～59 | float | lb_ref | 左后轮目标 ERPM |
| 60～63 | float | lb_fdb | 左后轮反馈 ERPM |
| 64～67 | float | rb_ref | 右后轮目标 ERPM |
| 68～71 | float | rb_fdb | 右后轮反馈 ERPM |
| 72～75 | float | diag_3 | CAN1接收帧计数 |
| 76～79 | float | diag_4 | VESC接收帧计数 |
| 80～83 | float | in_task | 当前底盘任务编号 |
| 84 | uint8 | checksum | `byte[2]...byte[83]` 累加和 |
| 85 | uint8 | tail | `DD` |

注意：代码中的 `tar_x/tar_y/tar_yaw` 和 `cmd_vx_true/cmd_vy_true/cmd_wz_true` 变量名属于历史遗留命名，当前实际承载的是 CAN诊断计数和任务状态，不能按变量名理解为目标位姿或真实速度。

### 3.3 状态值

```text
0：STATUS_IDLE
1：STATUS_EXECUTING
2：STATUS_CMD_SUCCESS
3：STATUS_CMD_FAILED
```

任务最终是否成功，应同时检查：

```text
status == STATUS_CMD_SUCCESS
last_command_id == 本次等待的命令 ID
```

不能只检查 `SUCCESS`，因为超时后脚本发送 STOP，STOP 本身也可能返回成功。

## 4. VESC 反馈帧

发送函数：

```c
SendVESCFeedbackToAgent()
```

### 4.1 基本格式

```text
帧头：       AA 55
帧类型：     56
Payload长度：72字节
总长度：     78字节
频率：       5 Hz，每200 ms发送一次
校验：       byte[2] 至 byte[75] 的无符号8位累加和
帧尾：       DD
```

### 4.2 字段定义

| 字节偏移 | 类型 | 字段 |
|---:|---|---|
| 0～1 | uint8[2] | `AA 55` |
| 2 | uint8 | 帧类型 `56` |
| 3 | uint8 | Payload长度 `72` |
| 4～11 | uint64 | STM32运行时间，单位 µs |
| 12～15 | int32 | LF逻辑反馈 ERPM |
| 16～19 | float | LF电流 A |
| 20～23 | float | LF duty |
| 24～27 | uint32 | LF在线状态 |
| 28～31 | int32 | RF逻辑反馈 ERPM |
| 32～35 | float | RF电流 A |
| 36～39 | float | RF duty |
| 40～43 | uint32 | RF在线状态 |
| 44～47 | int32 | LB逻辑反馈 ERPM |
| 48～51 | float | LB电流 A |
| 52～55 | float | LB duty |
| 56～59 | uint32 | LB在线状态 |
| 60～63 | int32 | RB逻辑反馈 ERPM |
| 64～67 | float | RB电流 A |
| 68～71 | float | RB duty |
| 72～75 | uint32 | RB在线状态 |
| 76 | uint8 | 校验和 |
| 77 | uint8 | `DD` |

这里发送的是经过逻辑轮位映射和反馈方向修正后的 ERPM，可以直接与状态帧中的四轮目标 ERPM 对比。

## 5. IMU 遥测帧

发送函数：

```c
SendIMUDataToAgent()
```

### 5.1 基本格式

```text
帧头：       AA 55
帧类型：     49
Payload长度：160字节
总长度：     166字节
频率：       50 Hz，每20000 µs发送一次
校验：       byte[2] 至 byte[163] 的无符号8位累加和
帧尾：       DD
```

控制内部仍以约200 Hz读取 HWT9053 数据；USART1只以50 Hz向上位机发送遥测。

### 5.2 姿态、角速度和加速度字段

| 字节偏移 | 类型 | 字段 |
|---:|---|---|
| 0～1 | uint8[2] | `AA 55` |
| 2 | uint8 | 帧类型 `49` |
| 3 | uint8 | Payload长度 `160` |
| 4～11 | uint64 | STM32运行时间，单位 µs |
| 12～15 | float | roll，单位 deg |
| 16～19 | float | pitch，单位 deg |
| 20～23 | float | 原始包角 yaw，单位 deg |
| 24～27 | float | 原始累计 yaw，单位 deg |
| 28～31 | float | gyro_x，单位 deg/s |
| 32～35 | float | gyro_y，单位 deg/s |
| 36～39 | float | gyro_z，单位 deg/s |
| 40～43 | float | acc_x，单位 g |
| 44～47 | float | acc_y，单位 g |
| 48～51 | float | acc_z，单位 g |

重要说明：

- IMU帧中的 yaw 是 HWT9053 原始角度数据，主要用于诊断。
- 实车调试发现原始 yaw 可能发生与真实运动不一致的瞬时跳变。
- 当前定角旋转真正使用的连续 gyro 积分控制航向，位于5 Hz状态帧的 `current_yaw` 字段。

### 5.3 IMU与CAN诊断字段

从偏移52开始依次发送28个 `uint32`：

| 序号 | 字节偏移 | 字段 |
|---:|---:|---|
| 1 | 52～55 | CAN状态 |
| 2 | 56～59 | CAN接收帧计数 |
| 3 | 60～63 | 有效IMU帧计数 |
| 4 | 64～67 | 最近CAN错误 |
| 5 | 68～71 | 最近标准ID |
| 6 | 72～75 | 最近扩展ID |
| 7 | 76～79 | 最近IDE |
| 8 | 80～83 | 最近RTR |
| 9 | 84～87 | 最近DLC |
| 10 | 88～91 | 最近数据类型 |
| 11 | 92～95 | 协议解析错误计数 |
| 12 | 96～99 | HAL错误计数 |
| 13 | 100～103 | 加速度帧计数 |
| 14 | 104～107 | 陀螺仪帧计数 |
| 15 | 108～111 | 角度帧计数 |
| 16 | 112～115 | yaw帧计数 |
| 17 | 116～119 | 配置尝试次数 |
| 18 | 120～123 | 配置完成状态 |
| 19 | 124～127 | 配置发送次数 |
| 20 | 128～131 | 配置发送错误次数 |
| 21 | 132～135 | 最近配置状态 |
| 22 | 136～139 | 初始化次数 |
| 23 | 140～143 | CAN启动状态 |
| 24 | 144～147 | CAN通知启用状态 |
| 25 | 148～151 | 最近接收tick |
| 26 | 152～155 | IMU在线状态 |
| 27 | 156～159 | FIFO0深度 |
| 28 | 160～163 | FIFO1深度 |
|  | 164 | 校验和 |
|  | 165 | `DD` |

正常运行期间不应自动调用 `HWT9053CAN_Config200HzPermanent()`。若以下字段非零，需要检查是否误恢复了自动配置逻辑：

```text
配置尝试次数
配置发送次数
配置发送错误次数
```

## 6. 发送调度

三类周期帧均由200 Hz底盘任务中的 `IMU_data_send()` 调度。

### 6.1 状态帧

使用 `HAL tick` 判断：

```c
if (now_tick - status_send_tick >= 200u)
```

因此设计周期为200 ms，即5 Hz。

### 6.2 VESC帧

使用 `HAL tick` 判断：

```c
if (now_tick - vesc_send_tick >= 200u)
```

因此设计周期为200 ms，即5 Hz。

### 6.3 IMU帧

使用DWT微秒时间判断：

```c
if ((now_us - imu_send_us) >= 20000u)
```

因此设计周期为20000 µs，即50 Hz。首次进入发送函数时会立即发送第一帧。

### 6.4 任务结束即时状态

`FinishTask()` 中会额外调用：

```c
SendStatusAndOdometryToAgent(&huart1);
```

因此状态帧除固定5 Hz外，在任务完成、失败或停止时还会即时多发送一帧。

## 7. DMA发送队列

发送函数不直接阻塞等待串口完成，而是调用：

```c
AgentTxWrite()
```

当前参数：

```text
发送环形队列：4096字节
单次DMA分块： 最大256字节
```

流程：

```text
遥测函数生成完整帧
    -> 写入4096字节发送环形队列
    -> AgentTxKick()
    -> USART1 DMA分块发送
    -> DMA完成回调继续发送队列中的剩余数据
```

如果队列剩余空间不足以容纳完整帧：

- 整帧不会写入；
- `agent_tx_drop_count` 增加；
- 状态帧发送失败时还会增加 `tx_status_error_count`。

当前周期数据占串口理论有效带宽约79.2%，余量不大。若提高IMU发送频率、扩大帧长度或增加新的周期帧，必须重新计算带宽，否则可能造成发送队列持续积压和丢帧。

## 8. 上位机解析对应关系

当前 Python 解析程序：

```text
keil/car_controlst.py
```

对应长度：

```python
status_frame_len = 86
IMU_FRAME_LEN = 166
VESC_FRAME_LEN = 78
```

调试脚本：

```text
keil/test_v2_protocol.py
```

修改固件帧长度、字段顺序、类型或频率时，必须同步修改 `car_controlst.py`，否则会出现帧错位、校验失败或字段含义错误。
